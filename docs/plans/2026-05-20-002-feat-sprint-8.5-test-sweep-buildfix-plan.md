# Sprint-8.5 Test Sweep + Build-Error Cleanup

## Summary

Restore the two frontend Vitest files Sprint-8 U11 deleted (httpClient + LoginScreen) under the new token-pair contract, fix 10 pre-existing .NET 9 compile errors across 5 csprojs, add one OwnerSeed real-Postgres integration test, and write 4 `docs/solutions/` entries capturing the patterns this sweep surfaced. Verification gate is **0 errors on `dotnet build ShopFlow.sln`** + every restored test green.

---

## Problem Frame

Sprint-8 U11 deleted `web/src/api/httpClient.test.ts` + `web/src/components/auth/LoginScreen.test.tsx` because their Sprint-6 single-JWT assumptions could not be cleanly patched onto the new token-pair + refresh-interceptor + subdomain-detect contracts; the rewrite was inflating the U11 commit. The contracts now sit uncovered at the unit-test tier — the routing layer + `useAuth.test.ts` token-pair suite catch most regressions, but the 401-refresh-interceptor edge cases (inflight-refresh guard preventing N-parallel-rotations, idempotency-key persistence across retry attempts, clearSession+ApiError on final failure) live below that coverage.

Separately, the full-solution build surfaces **10 distinct compile errors** across `StockSync.Application`, `Channel.UnitTests`, `Outbound.UnitTests`, `Inventory.UnitTests`, `Inventory.IntegrationTests`, `Inventory.Api`, and `Outbound.IntegrationTests`. None block Auth — each project's individual `dotnet build` succeeds in CI's existing matrix — but together they prevent a clean `dotnet build ShopFlow.sln` and erode the "production-ready" posture Sprint-7.5 set. They are accumulated drift from Sprint-3-redux contract evolution, Sprint-7.5 U3's incomplete namespace migration, Sprint-7's `SagaTransitionObserver` introduction without picking a FakeTimeProvider package, and Polly v7→v8 PredicateBuilder API drift left over from the Sprint-3-redux upgrade.

Finally, Sprint-8 U10 shipped `OwnerSeed.SeedAsync` with unit coverage for flag-resolution + stdout-echo only; the happy-path-against-real-tenant-DB integration test against Testcontainers Postgres was deferred. Closing it now puts the seed path under the same coverage every Sprint-1+ repository carries.

## Key Technical Decisions

1. **KTD1 — StockSyncOptions rename: nested `QueueCapacity` class → `QueueCapacitySettings`**. The existing convention in the same file already uses `*Settings` suffix for nested config classes (`TokenBucketSettings` at line 46, `BreakerSettings` at line 94). Renaming the nested class is the convention-consistent fix; renaming the property would force every consumer to update. Cost: zero consumers reference the nested class by name (only via `options.QueueCapacity`).

2. **KTD2 — Polly v8 PredicateBuilder shape**: `new PredicateBuilder<HttpResponseMessage>().Handle<HttpRequestException>().HandleResult(r => ...)` — generic moves from method to type. This is the only shape that compiles under Polly 8.4.2 (already pinned in `Directory.Packages.props`).

3. **KTD3 — `Microsoft.Extensions.TimeProvider.Testing 9.0.0` added to CPM**, then referenced from `ShopFlow.Outbound.UnitTests.csproj`. The package is the canonical .NET 9 FakeTimeProvider source. Document the addition in a new `docs/solutions/` note so Sprint-9+ doesn't re-derive the package choice.

4. **KTD4 — Per-test-class IRequestContext for Inventory.IntegrationTests SkuRepository tests**. The fixture pattern already exposes `tenant.BuildRequestContext()` (mirrors `OrdersListAndDetailEndpointTests.cs` line 336). Fix instantiates a fixture-bound RequestContext rather than introducing a fake — keeps tests on the same real-DB path as production code.

5. **KTD5 — Migrate.IntegrationTests is a new project, not a sub-suite of Auth.IntegrationTests**. OwnerSeed is the shopflow-migrate CLI's concern, not the Auth module's. The new project mirrors `tests/ShopFlow.Auth.IntegrationTests/ShopFlow.Auth.IntegrationTests.csproj` shape verbatim (rename `AuthTenantFixture` → `MigrateTenantFixture`); project-refs `shopflow-migrate.csproj` directly so test code can construct `OwnerSeed` via its public ctor. The CLI is `<OutputType>Exe</OutputType>` — confirmed test-project references to Exe csprojs work in .NET 9.

6. **KTD6 — SkuDimensions fix is a using-directive change, not a namespace consolidation**. Research confirmed there is only ONE `SkuDimensions` type (at `ShopFlow.Inventory.Domain.Catalog.ValueObjects`). The compile error is `SkusController.cs` referencing the type via a stale fully-qualified path `ShopFlow.Inventory.Domain.Catalog.SkuDimensions`. Replace the FQN with the `.ValueObjects` namespace; no type moves, no aggregate changes.

7. **KTD7 — StockReservationFailedV1 / StockReservedLineOutcomeV1 contract drift fixes in the test, not in the contract**. Research confirmed the contracts at `src/Shared/ShopFlow.Contracts/Inventory/` are the current canonical shape — `StockReservationFailedV1(OrderId, TenantId, LineOutcomes, OccurredAt)`. The test in `Outbound.IntegrationTests/Sagas/SagaTransitionsAuditFlowTests.cs` references obsolete shapes (extra `Reason` param + a `StockReservedLineOutcomeV1` type that no longer exists; current name is `LineOutcomeV1`). Update the test to match the contract.

8. **KTD8 — One commit per file group, not one commit per error**. Some errors cluster (e.g., the two Outbound.IntegrationTests AddProvider errors land in two consecutive controllers; the SagaTransitionsAuditFlowTests has 2 errors in adjacent lines). Group within a single csproj where possible to keep U-IDs ~10-12.

9. **KTD9 — Capture `docs/solutions/` notes during the sweep**, not at sign-off. Four notes: Polly v8 PredicateBuilder, TimeProvider.Testing CPM addition, SkuDimensions namespace + using-directive discipline, contract-evolution consumer-test churn. Each lands in the same commit as the fix so the learning compounds at the point it surfaces.

- Happy GET: adds `Authorization: Bearer <jwt>` + `X-Tenant-Slug` headers when auth state is populated.
- Happy POST: auto-generates ULID-shape `Idempotency-Key` when caller didn't supply one.
- Caller-supplied `idempotencyKey`: passed through verbatim, no ULID generation.
- JSON body: serialises non-string non-FormData objects + sets `Content-Type: application/json`.
- 2xx with JSON body: returns parsed `T`.
- 204 No Content: returns `undefined as T`.
- Non-2xx with JSON body: throws `ApiError` with parsed body.
- **401 + refresh succeeds**: original request retries with NEW access token (verified via second `fetchMock` call carrying new Bearer); idempotency-key on retry MATCHES the first attempt (audit dedup honest).
- **401 + refresh fails**: `clearSession()` called + `ApiError(401)` thrown; no retry attempt.
- **Concurrent 401 burst**: 3 parallel calls all fire 401; `refresh()` invoked EXACTLY ONCE (inflightRefresh guard); all 3 calls retry with the same successor token.
- **No refresh token in store**: 401 immediately throws (no refresh attempt).
- ApiError carries `status` + `body` for caller inspection.
