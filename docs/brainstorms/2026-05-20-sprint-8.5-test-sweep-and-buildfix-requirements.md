# Sprint-8.5 Test Sweep + Build-Error Cleanup

## Summary

Restore the two frontend test files Sprint-8 U11 deleted under the new token-pair contract, fix every pre-existing compile error in `dotnet build ShopFlow.sln`, and land the deferred OwnerSeed real-Postgres integration test. Verification target is **0 errors on full-solution build** + every restored test green.

---

## Problem Frame

Sprint-8 U11 deleted `web/src/api/httpClient.test.ts` + `web/src/components/auth/LoginScreen.test.tsx` because their Sprint-6 single-JWT assumptions could not be cleanly patched onto the new token-pair + refresh-interceptor + subdomain-detect surfaces; rewriting them in U11 would have inflated that commit. The two contracts are now uncovered at the unit-test tier — the routing layer + the new `useAuth.test.ts` token-pair suite catch most regressions, but the 401-refresh-interceptor edge cases (inflight-refresh guard, idempotency-key persistence, multi-tab race) live below that coverage and need dedicated assertions.

Separately, Sprint-7.5 shipped with a stray closing brace in `ISkuRepository.cs` + missing `using` directives in `UpdateSkuCommand.cs` — both broke the Inventory.Application compile path. CI presumably ran each project independently and missed the transitive surface; only when Sprint-8 U10 forced shopflow-migrate to pull Inventory.Application via project ref did the breakage become visible. Patching those two files exposed **7 additional latent errors** across Inventory.UnitTests, Inventory.IntegrationTests, Inventory.Api, Outbound.UnitTests, Outbound.IntegrationTests, Channel.UnitTests, and StockSync.Application — all from contract drift between Sprint-5/6/7/7.5 + Polly v8 + .NET 9 API drift. None of them block Auth, but together they prevent a clean `dotnet build ShopFlow.sln` and erode the "production-ready" posture Sprint-7.5 set.

Finally, Sprint-8 U10 shipped OwnerSeed with unit coverage for flag-resolution + stdout-echo only; the actual happy-path-against-real-tenant-DB assertion needed Testcontainers Postgres and was deferred. Closing it now gives the seed path the same integration coverage every other Sprint-1+ repository has.

## Key Decisions

- **D1.** OwnerSeed integration test lands in a new `tests/ShopFlow.Migrate.IntegrationTests/` csproj rather than under `ShopFlow.Auth.IntegrationTests/`. The OwnerSeed code lives in `tools/shopflow-migrate/` and is the CLI's concern; wedging its test into the Auth module's integration project blurs module ownership. The new project establishes the pattern for any future shopflow-migrate integration coverage (provision happy-path, archive flow, etc.).
- **D2.** Build-error fixes scope is **minimum-viable to compile**, not "improve the design." Each fix lands a one-line / one-file change documented in the commit body; no surrounding refactors. This is the discipline that keeps Sprint-8.5 one-week.
- **D3.** Tests restore against the CURRENT Sprint-8 contracts, not the Sprint-6 contracts. The deleted files referenced the old `useAuth.login(jwt)` + `/auth/login` URL + LoginUser shape; the new ones target `setSession(StoredSession)` + `/api/auth/login` + the rememberMe/tenant_slug body shape.
- **D4.** Sprint-8.5 unit count is ~10-12, similar shape to Sprint-7.5: U0 docs commit + U1-U2 frontend test restoration + U3-U10 one-error-per-unit fixes (groupable when files are co-located) + U11 OwnerSeed integration + U12 sign-off. Inline execution mode (no subagent dispatch) per Sprint-7.5/Sprint-8 lessons-learned.
