# Sprint-4.5 — Webhook receiver follow-up + scale-gate harness

## Summary

Close the four deferred items from the Sprint-4 sign-off as a single ~1-week closure unit: wire `WebhooksController` to the real per-channel parser via `IChannelAdapterFactory` (real `provider_event_id` replaces the body-hash stub); emit `OrderImportedV1` with `IProductMappingService`-resolved SKUs (replaces the placeholder event-type string); land `TenantWebhookHarness` + the three currently-`Skip`'d `MultiTenantWebhookScaleGateTests` bodies; runtime-smoke the Aspire mock-server round-trip where Docker is available. Tag `v0.6.1-sprint-4.5`; Sprint-5 Stock Sync Engine follows.

---

## Problem Frame

Sprint-4 shipped the channel-ingress pipeline end-to-end at the unit-test level but four load-bearing items were deferred at sign-off ([`docs/phase-gates/2026-05-13-sprint-4-signoff.md`](../phase-gates/2026-05-13-sprint-4-signoff.md)):

1. `WebhooksController` still derives the idempotency token from a `(body, signature)` hash instead of routing through the U5 `ShopeeWebhookParser` for the real `provider_event_id`. The UNIQUE-23505 catch still works, but the idempotency anchor is "this exact byte sequence" instead of "this marketplace-asserted event id" — replay through a slightly-different-but-semantically-identical payload (e.g., re-signed by Shopee's retry path) would NOT be caught.
2. The receiver writes a placeholder `"ShopFlow.Channel.Webhooks.WebhookReceivedV1"` string to the outbox `event_type` column instead of the canonical `OrderImportedV1` contract. The Outbound `OrderImportedConsumer` is wired and waiting; the producer side just hasn't been swapped over. Sprint-4 U6's product-mapping engine is similarly unwired on the emit path — every line item would come through with `InternalSku=null` if the chain ran end-to-end today.
3. `MultiTenantWebhookScaleGateTests` ships as three `Skip`'d `Category=Load` slots ([`tests/ShopFlow.Channel.IntegrationTests/MultiTenantWebhookScaleGateTests.cs`](../../tests/ShopFlow.Channel.IntegrationTests/MultiTenantWebhookScaleGateTests.cs)). The headline noisy-neighbor receiver-side assertions (per-tenant fairness floor ≥ 0.85 under 5×200rps × 5s, replay-100×-equals-1, cross-tenant signature → 401) have no harness body and therefore no measurement.
4. No runtime smoke of the Aspire mock-server wiring has happened on this dev machine (Docker daemon was not running during Sprint-4). The Sprint-4 sign-off accepted this as a documented Sprint-1-style deferral, but the actual round-trip remains unverified locally.

These compound: any Sprint-5 scale test that exercises the inbound side will be measuring the wrong shape until 4.5 closes (1) and (2), and the receiver-side fairness floor itself is unmeasured until 4.5 lands (3). The cost shape is small (~1 week of pure wiring + harness code) but the value compounds across every subsequent Phase-2 sprint.

## Requirements

**Webhook receiver wiring**

- R1. `WebhooksController` resolves the channel adapter via `IChannelAdapterFactory.ResolveFor(channel.ChannelType)` for the request's channel, calls its webhook parser, and uses the parser-returned `provider_event_id` as the idempotency token (replacing the existing `ExtractProviderEventIdStub` body-hash derivation).
- R2. Parser failures (malformed payload, missing required fields) surface as HTTP 400 with a stable error code; the existing 401 (signature) / 404 (unknown channel) / 200 (success or duplicate) status semantics are unchanged.
- R3. When the parser succeeds, the existing UNIQUE-23505 idempotency catch on `(channel_id, provider_event_id)` continues to detect replays — what changes is the *source* of the id (parser, not body-hash), not the dedupe mechanism.

**Outbox event emission**

- R4. The first-write outbox row carries the canonical `OrderImportedV1` contract (assembly-qualified type name + parsed payload) instead of the placeholder `"ShopFlow.Channel.Webhooks.WebhookReceivedV1"` string.
- R5. Each line item in the emitted contract carries an `InternalSku` resolved through `IProductMappingService` (Exact → in-process Levenshtein @ 0.6 → null per Sprint-4 U6's `HybridProductMappingService`), applied per line at receive time before the outbox row lands.
- R6. Unmapped lines (mapping returned null) emit with `InternalSku=null` and a warning log carrying the `(channel_id, external_sku)` pair; the row is NOT dropped. The Outbound `OrderImportedConsumer` already handles unmapped lines per Sprint-4 U8, so receive-time rejection is the wrong move.

**Multi-tenant scale-gate harness**

- R7. `TenantWebhookHarness` lands as a reusable integration helper: provisions N tenants with a Shopee channel and signing secret each, exposes a typed send method that signs a payload for a given tenant's channel with the right secret and posts through the real `WebhooksController` pipeline.
- R8. The three currently-`Skip`'d `MultiTenantWebhookScaleGateTests` get real bodies:
  - **Burst-200rps × 5 tenants × 5s sustained**: per-tenant p99 receiver-side latency < 200ms AND per-tenant fairness floor ≥ 0.85.
  - **Replay-100× of the same `(channel_id, provider_event_id)`**: exactly 1 `channel_outbox_messages` row exists in that tenant's DB after the burst.
  - **Cross-tenant signature**: tenant A's secret signing a payload posted to tenant B's `channel_id` → 401, zero rows written to either tenant's DB.
- R9. The harness uses Testcontainers Postgres + the real controller pipeline (no HTTP mocks). Tagged `Category=Load` so per-PR CI excludes them; nightly + on-demand CI runs them. Wall-time measurement on the dev machine remains conditional on Docker availability, per Sprint-1/3/4 precedent.

**Runtime smoke + sign-off**

- R10. Where Docker is available locally, `task up` brings the Aspire orchestrator up, the Shopee mock posts a signed webhook via `POST /__send-webhook`, and the resulting `OrderImportedV1` is observed in the Outbound saga state machine (saga reaches a state past `New`, confirming the consumer ran). Where Docker is unavailable, the Sprint-4.5 sign-off captures the same documented deferral Sprint-4 used.
- R11. Sprint-4.5 sign-off doc captures measured numbers (or documented deferrals), tag `v0.6.1-sprint-4.5` lands on the closing commit, CHANGELOG entry written, README + CLAUDE.md "Current stage" lines flip forward, plan frontmatter `status: active → completed`.

## Acceptance Examples

- AE1. **Covers R2.** Given the Shopee adapter is registered and a webhook payload arrives missing the `order_sn` field, when the receiver verifies the signature successfully and the parser raises a parse failure, the controller returns 400 with a stable error code and zero rows are written to the channel's tenant DB (no outbox row, no `webhook_events` row).
- AE2. **Covers R1, R3.** Given two POSTs of the same Shopee payload (identical body + signature) arrive 100ms apart, when the parser extracts `provider_event_id = "ORDER-2026-12345"` from each, the first call returns `{ isDuplicate: false }` and the second returns `{ isDuplicate: true }`; `channel_outbox_messages` contains exactly 1 row carrying `OrderImportedV1`.
- AE3. **Covers R4, R5, R6.** Given a webhook payload contains two line items with external SKUs `"SP-001"` (exact-mapped to internal `"INV-001"`) and `"SP-XYZ"` (unmapped), when the receiver processes it, the emitted `OrderImportedV1.Lines[0].InternalSku == "INV-001"` and `OrderImportedV1.Lines[1].InternalSku is null`, AND the outbox row's `event_type` column carries the assembly-qualified name of `OrderImportedV1`, AND a structured warning log is emitted for the unmapped line carrying `(channel_id, "SP-XYZ")`.
- AE4. **Covers R8 burst-200rps.** Given 5 tenants are provisioned with one Shopee channel each, when each tenant receives 200 signed webhooks per second for 5 sustained seconds (1,000 webhooks total per tenant, 5,000 across the fleet), per-tenant p99 receiver-side latency < 200ms and the fairness floor across tenants ≥ 0.85.
- AE5. **Covers R8 cross-tenant signature.** Given tenant A and tenant B are both provisioned with Shopee channels and distinct signing secrets, when a payload is signed with tenant A's secret and POSTed to the URL of tenant B's `channel_id`, the receiver returns 401, no row is written to either tenant's `webhook_events` table, and no row is written to either tenant's `channel_outbox_messages` table.

## Key Decisions

- **Route through `IChannelAdapterFactory.ResolveFor(channelType)`, not direct `ShopeeWebhookParser` injection.** Preserves the per-channel polymorphism Sprint-4 U5 established; when Sprint-6 adds Lazada, the controller is unchanged.
- **Unmapped SKUs emit with `InternalSku=null` (R6), not 4xx-reject the entire order.** Sprint-4 U8 already wired the Outbound `OrderImportedConsumer` to handle the null-line case (per the Sprint-4 sign-off's Channel→Outbound bridge description). Reject-at-receive would lose orders we could reconcile manually later, AND would violate the AGENTS.md §0 principle that correctness lives downstream (the producer's job is durable capture, not policy enforcement on partially-mappable orders).
- **Mapping resolution happens synchronously at the receiver, not in the consumer.** Keeps idempotency simple — `OrderImportedV1` is fully resolved before the outbox row lands; replays produce identical events. If 200rps × 5 tenants × Levenshtein lookup becomes a measurable hotspot in R8, the consumer-side approach becomes the alternative (recorded under Outstanding Questions).
- **Point release `v0.6.1-sprint-4.5`, not `v0.7.0-…`.** Matches the Sprint-2.5 precedent (the only other "point five" sprint to date). Sprint-4.5 ships no new capability surface — it closes deferrals — so the minor version doesn't increment.
- **Runtime smoke (R10) is conditional on Docker daemon availability.** Matches Sprint-1-redux U5, Sprint-3-redux U8, and Sprint-4 U9 precedent. CI is the real validation; local smoke is a confidence boost when available.
- **Branch convention**: `feat/phase-2-sprint-4.5-webhook-followup`, cut from `v0.6.0-sprint-4` not from the current Sprint-4 branch HEAD (matches the "branch from prior tag" pattern used since Sprint-1-redux).

## Dependencies / Assumptions

- `IChannelAdapterFactory.ResolveFor("shopee")` returns the `ShopeeAdapter` instance registered via DI ([verified in `src/Services/Channel/ShopFlow.Channel.Infrastructure/Adapters/ChannelAdapterFactory.cs`](../../src/Services/Channel/ShopFlow.Channel.Infrastructure/Adapters/ChannelAdapterFactory.cs)).
- `ShopeeWebhookParser` exposes a `Parse(bodyBytes)` returning `Result<WebhookEnvelope>` whose `ProviderEventId` is sourced from the Shopee `order_sn` field — Sprint-4 U5 ships this; happy-path covered by existing unit tests.
- `IProductMappingService.ResolveAsync(channelId, externalSku, ct)` returns `MappingResolution` (or equivalent) with method tag (Exact / Levenshtein / null) — Sprint-4 U6 ships `HybridProductMappingService` covering this.
- The Outbound `OrderImportedConsumer` is idempotent on `Order.ChannelExternalOrderId` UNIQUE and accepts lines with `InternalSku=null` — Sprint-4 U8 ships this with 3 consumer tests.
- Testcontainers Postgres + the Aspire `task up` chain (Postgres + PgBouncer + RabbitMQ + Shopee mock) work as documented in Sprint-4 U7/U9 when Docker daemon is available.
- Husky pre-commit + CSharpier remain non-blocking (CSharpier drift on 23 pre-existing files; Sprint-4.5 ships under the same posture documented in Sprint-4 sign-off).
- Sprint-4.5 inherits the per-tenant load test wall-time expectations from Sprint-3-redux U8 (mock-carrier latency shortened, `ClearAllPools()` between tests, warm-up phase) where applicable — the multi-tenant fairness measurement infrastructure is built on the same patterns.
