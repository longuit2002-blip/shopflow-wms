# Sprint-7.5 — Production-Ready Trade-off Closures

## Summary

Sprint-7.5 closes the seven Sprint-6/7 deferred trade-offs plus a cross-table index audit, executed to production-grade rigor (real indexes, mandatory cursor pagination, MT-redelivery defenses) rather than portfolio-demo cost-cutting. Roughly Sprint-4.5 cadence — ~10 units, ~1.5-2 weeks — bundling the SKU schema cut-over with a rich product model, full backend+frontend camelCase wire normalisation, flash-sale outbox dual-write to StockSync, deep-link URL state across filter + sort + page + drawer, reservation-ledger cursor pagination, UNIQUE constraint on `outbound_saga_transitions`, the 9-node SagaPipeline operator-observability split, and an index audit pass on already-shipped hot-path tables.

---

## Problem Frame

Sprint-6 shipped ShopFlow WMS's first frontend vertical slice (Inventory × Owner) with 10 named trade-offs deliberately deferred to land the slice on time. Sprint-7 closed three of those (#8 JwtBearer kernel-lift in spirit, #9 SignalR push, #3 partial via cross-module audit table) but added two more of its own (#1 UNIQUE constraint, #11 SagaPipeline collapse). Seven items remain open across two sprints' worth of debt.

The project's posture is now explicitly **production-ready, not portfolio-grade** — a real big-data seed will land later in the 12-sprint program, and the schema, query plans, pagination, and idempotency guarantees must be ready for it when it fires. That reframe shifts how to think about each deferred item: a "low-priority cosmetic" item like cursor pagination becomes mandatory because a million-row reservation ledger without LIMIT melts the page render; an "operator observability cosmetic" like the SagaPipeline node split becomes a real ops signal under load.

There's also a compounding cost. Two of the seven items — camelCase wire normalisation and the URL search-params pattern — propagate across every future frontend slice (Inbound, Channel, Analytics, Settings). The later they ship, the more code has to be re-touched. Sprint-2.5 was created specifically to redo an outbox migration "we should have shipped from the start"; the precedent says do convention-fixes early.

Sprint-7.5 is the consolidation pass before the next four module-frontend slices land. After it, every new module surface inherits camelCase wire + URL-state pattern + cursor-pagination pattern from day one, the SKU catalogue is a real database table, and the saga audit + flash-sale flag have production-grade idempotency.

## Key Flows

- F1. **Owner edits SKU rich metadata.**
  - **Trigger:** Owner clicks edit on a SKU row in the Inventory list.
  - **Actors:** A1, A3
  - **Steps:** Modal opens with name / category / threshold / weight / dimensions / description / image URL / barcode / brand fields. Owner edits a subset. Save persists to the `skus` table; row updates in the list.
  - **Outcome:** Database holds the canonical rich SKU record; no in-memory singleton anywhere.
  - **Covered by:** R1, R3, R4

- F2. **Owner flips flash-sale toggle.**
  - **Trigger:** Owner clicks the flash-sale switch on a SKU row.
  - **Actors:** A1, A3, A4
  - **Steps:** Inventory writes the flag locally on the `skus` row, emits `SkuFlashSaleChangedV1` to the outbox. Dispatcher publishes to RabbitMQ. StockSync consumer upserts the `sku_flags` row idempotently.
  - **Outcome:** Both Inventory and StockSync converge on the new flash-sale state; flash-sale priority routing in StockSync respects the new flag within seconds.
  - **Covered by:** R7, R8, R9

- F3. **Operator opens reservation ledger drawer on a high-volume SKU.**
  - **Trigger:** Operator clicks a SKU row in Inventory list.
  - **Actors:** A1, A3
  - **Steps:** Drawer opens. First cursor-bounded window fetches (default page size). "Load more" button shows when more rows exist. Clicking advances by opaque cursor.
  - **Outcome:** Drawer stays responsive against a million-row ledger; page render time stays sub-200ms regardless of total row count.
  - **Covered by:** R13, R14, R15

- F4. **Operator deep-links into a filtered list view with drawer pre-opened.**
  - **Trigger:** Operator follows a shared URL like `/inventory?filter=lowStock&sort=availableAsc&page=3&selected=SKU-001` (for example, from an incident-triage Slack message).
  - **Actors:** A2, A6
  - **Steps:** Page loads, filter strip shows "Low stock", table sorts by available ascending, page 3 displays, LedgerDrawer opens on SKU-001. Closing the drawer clears `selected` from URL; back button traverses prior URL states.
  - **Outcome:** Full route state is shareable, reloadable, and back-button-navigable.
  - **Covered by:** R10, R11, R12

- F5. **Outbound saga receives MT redelivery of an already-audited transition.**
  - **Trigger:** RabbitMQ redelivers a `SagaTransitionedV1` event (transient ack failure, network partition recovery, etc.) for a transition already recorded.
  - **Actors:** A5
  - **Steps:** Observer attempts INSERT into `outbound_saga_transitions`. The composite UNIQUE constraint trips a 23505. Catch handler swallows as idempotent no-op, logs at debug level.
  - **Outcome:** No double-row in the audit table; downstream hub event is also de-duplicated by the existing relay's idempotency.
  - **Covered by:** R16, R17

## Requirements

**SKU catalogue model (#1)**
- R1. The Inventory schema includes a real `skus` table per tenant with: `name`, `category`, `threshold`, `weight_grams`, `dimensions` (jsonb), `description`, `image_url`, `barcode`, `brand`, `is_flash_sale`. The InMemorySkuMetadataStore singleton is removed at the same time.
- R2. The new `skus` table has production indexes for big-data access: btree on `category`; partial btree on `is_flash_sale` where true; partial UNIQUE on `barcode` where not null. No tsvector full-text yet.
- R3. The Owner-facing SKU edit modal reads and writes all rich columns; existing Sprint-6 create-modal extends to capture rich fields at creation time.
- R4. The migration is live-safe: new table only, no destructive ALTERs on hot-path tables; standard EF Core migration pattern.

**Wire format normalisation (#2)**
- R5. All HTTP endpoints (existing + new, across every module API) serialize and deserialize JSON in camelCase. No PascalCase wire shape remains anywhere.
- R6. Frontend TypeScript types reflect the camelCase shape; Vitest fixtures, MSW handlers, and component-level mocks are migrated in the same pass; integration tests pass with no other code changes after the flip.

**Flash-sale dual-write (#3)**
- R7. When Owner flips flash-sale on Inventory, Inventory persists the flag locally on the `skus` row AND emits a `SkuFlashSaleChangedV1` outbox event.
- R8. StockSync consumes `SkuFlashSaleChangedV1` and upserts the `sku_flags` row idempotently via the existing UNIQUE-23505 catch pattern (Sprint-5 U7 KTD7).
- R9. Under MT redelivery, the dual-write remains idempotent on both sides; flap sequences (A→B→A) converge on the FIFO-final state thanks to per-`(tenant, sku)` outbox ordering.

**URL search-params persistence (#4)**
- R10. Inventory and Orders list pages persist filter values, sort column, sort direction, page (or cursor), and drawer-open state in URL search parameters.
- R11. Reload preserves all list state; back button traverses filter changes; deep-links open the same view for any user with the same permissions; clearing the drawer clears its search-param.
- R12. The pattern is generalizable as a reusable helper so any future module list page (Inbound POs, Channel mappings, Analytics filters, Settings) inherits the convention without re-deriving it.

**Reservation ledger cursor pagination (#5)**
- R13. The `reservations_ledger` read path supports cursor-based pagination via an opaque base64 cursor encoding the last-row's `occurred_at` + `id`.
- R14. The LedgerDrawer UI fetches an initial page (configured page size) and shows a "Load more" button when more rows exist; clicking advances by cursor; no infinite scroll, no numbered pages.
- R15. Reservation-ledger queries are bounded — never `SELECT *` without LIMIT — and stay sub-200ms first-page render against a per-tenant million-row seed.

**Saga audit double-write defense (#6)**
- R16. The `outbound_saga_transitions` table adds a UNIQUE constraint on `(order_id, occurred_at, to_state)`.
- R17. The SagaTransitionObserver catches 23505 violations as idempotent no-op; under MT redelivery no double-row is recorded; the SagaTransitionedV1 outbox emit is not duplicated either.

**SagaPipeline operator observability (#7)**
- R18. The SagaPipeline component renders 9 nodes (was 8): the collapsed "Placed" node splits into `Created` and `AwaitingReservation`, surfacing the bus-latency-vs-Inventory-consumer-latency distinction visually.
- R19. Visual treatment for the new nodes matches existing states (`completed` / `current` / `pending`); `aria-current="step"` semantics intact; failure-caption rendering unchanged.

**Index audit on shipped tables (new unit)**
- R20. An audit pass reviews indexes on hot-path tables — `reservations_ledger`, `outbound_orders` + `outbound_order_lines`, `outbound_saga_transitions`, `webhook_events`, `stock_sync_push_log`, `stock_items` + `bins` + `stock_item_bins`, `purchase_orders` + `receivings`, `channels`, `product_mappings`, `sku_flags` — and adds missing indexes against expected big-data query plans.
- R21. The audit ships as a single migration per affected module; outbox tables are excluded (dispatcher access pattern is already bounded by claim+ack); the audit identifies the indexes added in commit message + sign-off, not in this doc.

- AE2. **Covers R7, R8, R9.** Given MT redelivers a `SkuFlashSaleChangedV1` event for `SKU-123 → is_flash_sale=true` that was already processed, when StockSync consumer attempts to upsert `sku_flags(SKU-123, true)`, the 23505 catch returns the existing row without double-writing, and no second downstream event fires.
- AE3. **Covers R11.** Given an Owner deep-links to `/inventory?filter=lowStock&sort=availableAsc&page=3&selected=SKU-001`, when the page loads, the filter strip shows "Low stock", the table sorts by available ascending, page 3 displays, and the LedgerDrawer is open on SKU-001 with its first cursor page rendered.
- AE4. **Covers R15.** Given a tenant with 5M rows in `reservations_ledger` for SKU-X, when the Owner opens the LedgerDrawer for SKU-X, the first page returns in under 200ms and only the cursor-bounded window of rows is rendered; subsequent "Load more" clicks each advance by one page without growing memory footprint.
- AE5. **Covers R17.** Given the SagaTransitionObserver receives a redelivered consume for an `(order_id, occurred_at, to_state)` triple that already exists, when the observer attempts INSERT into `outbound_saga_transitions`, the 23505 is caught, no duplicate row is recorded, and the operation logs at debug level rather than warning or error.
- AE6. **Covers R18.** Given a saga that has progressed through Created → AwaitingReservation → Reserved, when the operator views the SagaPipeline, three completed nodes are highlighted in the 9-node strip; the previously collapsed states are visible and distinguishable.
- AE7. **Covers R12.** Given a Sprint-8 developer building the Inbound POs list page, when they need URL-state persistence, they import the generalised helper rather than writing list-state-to-URL plumbing from scratch; the same `filter + sort + page + drawer` convention propagates without re-derivation.

## Key Decisions

- **Production-ready as the bar, not portfolio-demo.** Cursor pagination is mandatory (not "for later"); indexes are baked into every new schema; MT-redelivery defenses are required, not optional.
- **SKU columns: rich product model (10 cols).** Includes `is_flash_sale` for symmetry with the dual-write source. Avoids future migrations during Sprints 8-12 when Inbound put-away wants `weight_grams`, Outbound pack-weight warnings want it, and Channel mapping cards want `description` / `image_url`. Same-migration cost is near-zero; staged migrations have higher carrying cost.
- **camelCase flip is all-or-nothing across every endpoint, existing and new.** Inconsistent wire shape is the worst outcome — every reader has to remember which endpoint is which era. One pass, all endpoints, every frontend type and fixture updated together.
- **Flash-sale dual-write goes via outbox event (`SkuFlashSaleChangedV1`), not controller-level coupling.** Matches Sprint-5's `StockLevelChangedV1` precedent; two-phase HTTP coupling under failure is the trap we already avoid for `stock_changed`.
- **URL search-params persists full route state** (filter + sort + page + drawer-open). Drawer-open in URL adds slight complexity but pays off in deep-link UX and propagates cleanly to every future module list page.
- **Cursor pagination UX: "Load more" button + opaque base64 cursor.** Not infinite scroll (mis-fits operator triage workflow), not numbered pages (mis-fits append-only time-ordered data).
- **UNIQUE on `outbound_saga_transitions`: composite `(order_id, occurred_at, to_state)`.** Observer catches 23505 as idempotent no-op (no `WHERE NOT EXISTS` pre-check; cheaper and racier-safe than a check-then-insert).
- **SagaPipeline becomes 9 nodes; `CompensatingReservation` stays as inline failure caption.** Splitting Created + AwaitingReservation surfaces real operational signal (bus latency vs Inventory consumer latency). Compensating doesn't earn its own node because it's a failure-mode branch, not a happy-path station.
- **8th unit added: index audit on already-shipped hot-path tables.** Closes a production-readiness gap that "fix things as you encounter them" would never close; one migration per affected module.
- **All Sprint-7.5 migrations are live-safe** (NULLABLE cols + new tables + new indexes only; no destructive ALTERs); standard EF Core migration pattern; `CREATE INDEX CONCURRENTLY` deferred to a future production-migration sprint.
- **Sprint-7.5 ships against the existing dev-mode baked JWT.** Real auth is Sprint-8.
- **Subagent dispatch pattern from Sprint-7 carries forward.** Expect 3-4 parallel rounds where file-disjoint; orchestrator commits serially after diff review. Shared-directory mode (worktree isolation still deferred since `.claude/worktrees/` not yet gitignored).
- **Branch from `v0.10.0-sprint-7-orders`; tag `v0.10.1-sprint-7.5`.** Matches Sprint-2.5 `v0.4.1` + Sprint-4.5 `v0.6.1` point-release pattern.
