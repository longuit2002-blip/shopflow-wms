3. KTD1 — Bet kỹ thuật cần bạn xác nhận

Brainstorm R1 nói "consume 3 event Sprint-3 đã có". Đọc code thì 2 trong 3 event không có SKU → StockSync phải coupling sang Outbound. Plan đề xuất bổ sung 1 event mới sạch hơn.
Option A — Literal brainstorm R1 (giữ nguyên)
StockSync subscribe 3 event:
  • StockReservedV1 — có SKU ✓
  • StockReleasedV1 — chỉ có OrderLineIds, không có SKU
  • StockConfirmedV1 — không có per-line gì cả
⚠ StockSync phải gọi Outbound để map line → SKU
⚠ Cross-module coupling thừa
⚠ Race: line có thể đã xoá khi StockSync hỏi
Option B — KTD1 đề xuất (recommended)
Thêm 1 contract mới:
StockLevelChangedV1(
  TenantId, Sku,
  AvailableToSell,
  OccurredAt)
Inventory emit event này từ StockChangedEvent domain event (đã có sẵn trong code, comment ghi rõ "for the stock-sync engine").
✓ StockSync chỉ subscribe 1 event
✓ Không touchout Outbound
✓ Self-contained, đúng intent design v3.0

4. Các KTD còn lại (đỡ rủi ro hơn)

KTD2 — Flash-sale flag ở đâu?
Bảng riêng stock_sync_sku_flag trong StockSync DbContext.
Không attach ProductMapping của Channel → StockSync sở hữu lifecycle flag, loose coupling.
KTD3 — Library cụ thể
Token bucket = System.Threading.RateLimiting.TokenBucketRateLimiter (.NET 9 built-in)
Queue = System.Threading.Channels.Channel<T> bounded
Breaker = Polly v8 AddCircuitBreaker (tái dùng pipeline Sprint-4)
Không thêm thư viện mới; built-in .NET 9 đủ cho portfolio.
KTD4 — Coalescing implementation
ConcurrentDictionary<(TenantId, Sku, Channel), Entry> + PeriodicTimer 500ms flush.
Per-tenant qua key tuple; không cần lock; flush job push entries qua priority queue.
KTD5 — State persistence
Persist: push_log (audit) + sku_flag.
In-memory: coalescing buffer, queue, token bucket, breaker state.
Restart = warm-up (mất ~500ms throttle); chấp nhận cho portfolio MVP. Phase-3 cân nhắc Redis-back-store.
