# Sprint-10.5 — Trade-off closures (post Sprint-10)

## Summary

A ~1-week point release closing the five trade-offs Sprint-10 deferred. Sprint-10.5 extends frontend `usePerm()` gating to every interactive control across Inventory / Orders / Inbound business pages, attaches the `hub.connect` policy to `TenantHub`, adds exhaustive 403 wire-shape Docker integration tests covering all 33 actions migrated in Sprint-10, fixes the frontend `web/src/api/admin.ts` `PERMISSION_KEYS` catalog drift, and pins a contract test asserting frontend ↔ backend key set equality so CI fails on future drift. Same point-release cadence as Sprint-2.5 / 4.5 / 7.5 / 8.5 / 9.5.

---

## Problem Frame

Sprint-10 flipped the backend authorization gate from class-level `[Authorize]` / `[Authorize(Roles="Owner")]` to per-action `[Authorize(Policy = PermissionKeys.X)]` across the four catalogued business-module controller groups — 33 actions referencing the 24 keys in [`PermissionKeys.All`](../../src/Shared/ShopFlow.SharedKernel/Authorization/PermissionKeys.cs). The Sprint-10 sign-off ([`docs/phase-gates/2026-05-22-sprint-10-signoff.md`](../phase-gates/2026-05-22-sprint-10-signoff.md)) explicitly named five trade-offs deferred to a follow-on point release.

Today the frontend Sprint-9.5 `usePerm()` gate is wired at **route level** (Sidebar items + `requirePermission()` route-guard helper on the three admin routes + `RolePermissionsEditor` Owner-locked column) but NOT at **action level** — the buttons / toggles / inline edits on Inventory / Orders / Inbound pages all render unconditionally. The backend Sprint-10 gate would reject an unauthorized request with 403, but the UI shows the actionable surface anyway. That's defensible while only Owner is provisioned (Owner carries all 24 keys via `RolePermissionsSeed`), but the moment Sprint-11 lands a non-Owner role with a narrower `perm[]` set, users will see buttons they cannot use and click them only to receive 403s — a clearly broken UX.

The `hub.connect` permission key is catalogued in `PermissionKeys.All` but unattached to `TenantHub` (Sprint-7 single-hub-host on Outbound.Api). Frontend `useSignalR` connection attempts authenticate via JwtBearer but no per-permission gate fires; any JWT carrying any keys can connect.

Sprint-10 trusted the policy-mechanism contract via Sprint-9.5's `PermissionPolicyCompositionTests` (DI-shape unit test). Runtime 403 assertions against real JWTs with narrowed perm-claim sets do not exist yet — Sprint-10's reflection tests pin attribute presence but not enforcement behavior. The first time a non-Owner JWT hits a covered endpoint will be Sprint-11's integration tests.

Phase-1 research during the Sprint-10 brainstorm flagged that the frontend `web/src/api/admin.ts` `PERMISSION_KEYS` catalog has drifted significantly from backend `PermissionKeys.All` — roughly 9 of 12 entries are out of sync (mostly wrong string literals: `outbound.orders.confirm-pick` vs backend `outbound.orders.pick-confirm`; `inventory.skus.create` / `.update` vs single `inventory.skus.write`; `inbound.pos.create` vs `inbound.pos.write`; `hub.tenant.read` / `hub.tenant.write` vs `hub.connect`; `notification.dlq.read` doesn't exist on backend). `RolePermissionsEditor` ships against stale strings — saves are silently dropped or transformed by the backend `RolePermissionsCommandHandler` validation depending on the impl detail. Invisible today because only Owner is provisioned and Owner has all keys; becomes a privilege-escalation vector when Sprint-11's Picker role lands.

Sprint-10.5 closes all five gaps in one ~1-week bundle so Sprint-11 can ship the first multi-role surface against a tight RBAC story.

## Requirements

### Frontend per-button gating

- **R1.** Every public interactive control on Inventory / Orders / Inbound business pages consults `usePerm()` for visibility / disabled state. Scope of "interactive control": buttons (`<button>`), toggles (`role="switch"`), inline edits (the Sprint-7.5 threshold-edit pattern), action dropdowns, action-bearing menu items. Read-only displays (status pills, tooltips, KPI numbers) are NOT in scope.
- **R2.** Gating policy: when the user lacks the required permission, the control is hidden by default. Disabled-with-explanation tooltip is acceptable as an alternative when the affordance would be missed entirely (e.g., the `Adjust Stock` button on an empty inventory table — better to show disabled than hide because the empty state then makes no sense). Implementer picks per control during the planning pass; the brainstorm permits both shapes.
- **R3.** Existing route-level gates via `requirePermission()` (Sprint-9.5 U8) remain authoritative. R1's control-level gates layer on top, not replace.

### Hub permission

- **R4.** `TenantHub` (in `ShopFlow.SharedKernel.Infrastructure.SignalR`, mapped by Outbound.Api per Sprint-7 single-hub-host topology) gains `[Authorize(Policy = PermissionKeys.HubConnect)]`. A JWT carrying any other Sprint-10 keys but missing `hub.connect` cannot establish a hub connection.
- **R5.** Connection rejection surfaces to the frontend as a transport-level failure that `useSignalR`'s existing state machine treats as "disconnected" (R13 polling fallback re-engages). No new error shape needed.

### Backend 403 wire-shape coverage

- **R6.** Per-controller integration test classes cover all 33 actions migrated in Sprint-10. One test per action: submit a valid JWT whose `perm[]` claim omits the action's required key but includes other keys (so authentication succeeds + the gate fails on the policy, not on auth). Assert HTTP 403 response.
- **R7.** Each 403 test asserts the response carries a stable error code (the existing ASP.NET Core authorization-failure response shape — likely empty body + `WWW-Authenticate: Bearer error="insufficient_scope"` or the .NET 9 default). The exact shape is execution-time discovery; the test pins whatever the framework returns so a future framework upgrade that changes it fails fast.
- **R8.** Docker-backed via Testcontainers Postgres + Redis (Sprint-1+ posture). Tests carry `[Trait("Category", "Integration")]`; Skip-marked locally for dev machines without Docker daemon; CI runs the full suite via the existing Docker-backed nightly + per-PR jobs.
- **R9.** Orphan keys (`outbound.orders.cancel`, `hub.connect`) are NOT covered by these 33 tests — `outbound.orders.cancel` has no action attachment; `hub.connect` is exercised by R4's hub-level test, not as one of the 33 controller-action tests.

### Frontend catalog drift fix

- **R10.** `web/src/api/admin.ts` `PERMISSION_KEYS` is rewritten to contain exactly the 24 keys present in backend `PermissionKeys.All`. String values match backend constant values exactly (e.g., `inventory.skus.write`, not `inventory.skus.create`/`.update`). Per-module grouping in the file mirrors backend organization (Auth admin / Inventory / Outbound / Inbound / Hub).
- **R11.** `OWNER_CRITICAL_KEYS` client mirror (Sprint-9.5 U7) is updated to match backend `PermissionKeys.OwnerCritical` — same 9 entries, same string values.
- **R12.** `RolePermissionsEditor` continues to render its 3-column matrix (Owner / Picker / Dispatcher) against the corrected catalog. The Owner column stays locked per Sprint-9.5 KTD11; the Picker / Dispatcher columns may show toggles for keys that no UI surface uses yet (orphan keys `outbound.orders.cancel` + `hub.connect`) — that is the intended shape under R13's set-equality contract.

### Catalog contract pin

- **R13.** A contract test asserts frontend `PERMISSION_KEYS` and backend `PermissionKeys.All` are set-equal: every backend key has a frontend constant; every frontend constant maps to a backend key. Drift in either direction fails CI with a clear message naming the offending key(s).
- **R14.** The test reads both sources at test-time. Implementation strategy (frontend Vitest test importing both via a fixture-generated TS file; or backend integration test parsing the frontend admin.ts file; or a build-time codegen step) is deferred to the planning pass — the contract shape is fixed at set equality regardless.

## Acceptance Examples

- **AE1. Covers R1, R2, R3.** Given a JWT whose `perm[]` lacks `inventory.adjust`, when the user navigates to `/inventory`, the "Adjust Stock" button is hidden (or disabled with tooltip). The KPI strip still renders; the SKU table list still polls; the per-row Edit button is hidden if the user also lacks `inventory.skus.write`. Existing route-level access via `requirePermission()` still admits the user (read-only browsing remains).
- **AE2. Covers R4, R5.** Given a JWT carrying `inventory.read` but NOT `hub.connect`, when `useSignalR` attempts to connect to the hub, the connection is rejected at the policy layer. The frontend hub state is "disconnected"; `useInventoryQuery` and `useOrdersQuery` fall back to 2-s polling per Sprint-7 R13. No console error spam; no infinite reconnect storm.
- **AE3. Covers R6, R7, R8.** Given a JWT whose `perm[]` claim is `["inventory.read"]` (excludes `inventory.adjust`), when the test submits `POST /api/inventory/adjustments`, the response is HTTP 403. The test fires against real Postgres + Redis via Testcontainers; locally it Skip's; in CI it runs and passes.
- **AE4. Covers R10, R11.** Given Sprint-10.5 ships, when a developer inspects `web/src/api/admin.ts`, `PERMISSION_KEYS` contains 24 entries that are string-equal to `PermissionKeys.All`. `OWNER_CRITICAL_KEYS` contains 9 entries string-equal to `PermissionKeys.OwnerCritical`. `RolePermissionsEditor` renders without console warnings about unknown keys.
- **AE5. Covers R13, R14.** Given a developer adds a new key `inventory.transfer` to backend `PermissionKeys.cs` but forgets to update `admin.ts`, when CI runs, the contract test fails with a message naming `inventory.transfer` as backend-only. Conversely, if a developer adds a stale string to `admin.ts` that doesn't exist on backend, the test fails naming that string as frontend-only.

## Success Criteria

- Every interactive control on Inventory / Orders / Inbound business pages is perm-aware; a JWT with a narrowed `perm[]` set sees a UI that matches what the backend allows (no clicking buttons that 403).
- `TenantHub` enforces `hub.connect`; JWTs without the key cannot establish a SignalR connection.
- 33 Docker-backed integration tests pin every Sprint-10 action's enforcement behavior at runtime — not just attribute presence (Sprint-10's reflection tests) but actual 403 response on a perm-mismatch.
- Frontend `admin.ts` `PERMISSION_KEYS` exactly mirrors backend `PermissionKeys.All` and `OWNER_CRITICAL_KEYS` mirrors `PermissionKeys.OwnerCritical`. The drift Phase-1 research flagged is closed.
- The contract test makes future drift impossible to ship — a developer adding a key on one side and forgetting the other gets CI feedback before merge.
- Sprint-11 inherits a defense-in-depth RBAC posture: route-level gating + control-level gating + backend per-action gates + runtime-tested 403 behavior + frontend-backend catalog alignment. The first non-Owner role can be provisioned against this stack and its `perm[]` set can be narrowed with confidence.

## Key Decisions

- **Comprehensive over targeted across all three scope axes.** Per-button gating covers every interactive control (not just mutation-bearing buttons). 403 tests cover all 33 actions (not representative sampling). Catalog contract uses set equality (not subset pin). Rationale: Sprint-10.5 closes the visible gap before Sprint-11 introduces a non-Owner role; the marginal effort of comprehensive scope is small compared to the cost of a half-gated Sprint-11 surfacing UX or security issues.
- **Set equality on the catalog contract expands `admin.ts` to all 24 backend keys.** Including the two orphan keys (`outbound.orders.cancel`, `hub.connect`). `RolePermissionsEditor`'s Picker / Dispatcher columns will show toggles for keys that no UI surface uses yet. That is the intended shape — the editor is a role-administration tool, not a "what works today" tool. A future `CancelOrder` action attaching to `outbound.orders.cancel` should not require an admin.ts update; the catalog already has it.
- **Hub permission as a single policy attribute on `TenantHub`, not per-method.** The hub has no public methods today beyond the implicit connect/disconnect lifecycle; `[Authorize(Policy = PermissionKeys.HubConnect)]` at the hub class level is the right shape. If Sprint-11+ adds hub methods (server-to-client invocations or client-callable methods), those would gain per-method policies on top.
- **403 test response-shape assertion is execution-time discovery.** The exact body / header shape ASP.NET Core's policy-mismatch path returns (vs auth-mismatch) depends on framework version + middleware configuration. The test pins whatever it actually returns and updates if a framework upgrade changes it. R7's job is to lock the current shape, not to specify it ahead of seeing it.
- **Disabled-with-tooltip vs hidden is a per-control planning decision.** The brainstorm allows both shapes (R2). The default is hidden; disabled-with-tooltip applies where the affordance's absence would make the surrounding UX confusing (e.g., an empty inventory table with no "Adjust Stock" button looks broken even if the user can't act).

## Scope Boundaries

### In-sprint scope additions surfaced during brainstorm

- None — the five-item scope inherited from Sprint-10 sign-off is the full sprint.

### Carried from origin (unchanged)

- No new permission keys; `PermissionKeys.All` stays at 24.
- Orphan keys (`outbound.orders.cancel`, `hub.connect`) stay in the catalog. `hub.connect` becomes applied via R4; `outbound.orders.cancel` remains catalogued-but-unapplied.
- `AuthController` self-service endpoints (logout / me-password / mfa-enroll-begin / mfa-disable / mfa-recovery-codes) keep bare `[Authorize]` (Sprint-10 KTD7).
- Ungated live controllers (`ChannelController`, `ProductMappingsController`, `SkuFlagsController`, `SyncStateController`, `PutAwayController`) stay ungated — requires new permission keys, separate sprint.
- Stub controllers (`OutboundController`, `AnalyticsController`) stay ungated.
- `WebhooksController` (Channel) keeps `[AllowAnonymous]` (HMAC-gated).

### Deferred to follow-up work

- **Sprint-9.6 frontend hygiene** — a11y harness extension across the 9 Sprint-9.5 components (5 auth screens + RecoveryCodesDisplay + 3 admin pages); ProfileSecurityScreen `useMe()` migration; `/admin/users` TanStack Query migration with cache invalidation on Reset MFA + Unlock. Separate workstream; doesn't unblock Sprint-11.
- **Sprint-11 — first multi-role surface.** Picker or operations dispatcher role with a deliberately narrower `perm[]` set than Owner. First end-to-end test that per-permission gating actually rejects unauthorized requests at the user-flow level (not just R6's per-action runtime tests). Sprint-10.5 is a precondition.
- **`CancelOrder` action on `OrdersController`** — orphan key `outbound.orders.cancel` attachment surface. Or remove the key if compensation-via-saga becomes canonical.
- **Inventory.Api + Outbound.Api + Inbound.Api migration to `UseShopFlowSecurityPipeline()`** — separate cleanup; Sprint-10 KTD4 keeps the hand-wired pattern for cross-module consistency.
- **`Program` partial-class exposure on Inbound.Api** — for `WebApplicationFactory<Program>` integration tests if Sprint-10.5 R6 needs to boot Inbound.Api via that path. Implementer decides during planning.
- **Per-permission migration of remaining ungated live controllers** — requires new keys; deliberately out of Sprint-10 and Sprint-10.5 scope.
- **Phase-3 observability dashboards** including per-permission denial rates per tenant — Phase-3 work after Sprint-11.

## Risk Analysis

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| `hub.connect` policy attachment breaks the existing Sprint-7 hub flow because frontend `useSignalR` connection attempts use a JWT that today carries all 24 keys (Owner) but production cookies / refresh-token rotation paths might transiently issue a JWT without `hub.connect`. | Low | Medium | Owner always has all 24 keys via `RolePermissionsSeed` — the only way to get a JWT missing `hub.connect` is via a future non-Owner role. Sprint-10.5 lands before Sprint-11; the policy is in place when the first non-Owner role can exist. Test: a manual smoke pass of `/inventory` + `/orders` post-Sprint-10.5 to confirm hub connects under Owner JWT. |
| Per-button gating across many components introduces visual regressions (button placement / table column widths shift when buttons hide). | Low-Medium | Low | Each control's "hidden" rendering keeps DOM space minimal (use `display: none` only when the whole row hides; otherwise use the disabled state). A11y harness from Sprint-9.5 catches structural regressions; visual regressions caught in manual smoke. |
| 33 Docker integration tests significantly slow the CI nightly + per-PR jobs. | Medium | Low | Tests Skip locally per Sprint-1+ posture; CI runs in parallel where the test framework supports it. Each test is bounded — single HTTP call + assertion — so wall-time is dominated by Testcontainers startup which the existing fixture already amortizes across the test class. |
| Set-equality contract test (R13) is brittle — false-positive failures from temporary unmerged catalog state during multi-PR features. | Low | Low | The test reads both sources at test-time; the test failure is a deliberate guard against split-PR catalog drift. Mitigation: if a feature legitimately needs to land a key on one side first, the implementer can `[Skip]` the contract test in their PR with a TODO comment + a follow-up PR to re-enable. The pattern is documented in the test class XML doc. |
| Disabled-with-tooltip approach (R2 alternative) requires careful aria-describedby wiring to avoid screen-reader confusion; getting it wrong is an a11y regression. | Low | Medium | Sprint-9.5 KTD11 `aria-describedby` pattern on `RolePermissionsEditor` Owner column lock-icon is the reference. Implementer mirrors that pattern; Sprint-9.6 a11y harness extension (deferred) would catch any regressions when it lands. |
