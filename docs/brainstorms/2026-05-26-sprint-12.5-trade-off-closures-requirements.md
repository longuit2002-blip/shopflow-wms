# Sprint-12.5 — Trade-Off Closures

## Summary

Sprint-12.5 is a ~1-week polish release that closes the five Sprint-12 trade-offs explicitly carried forward in the sign-off: wire `auth_audit_log` into the 14 Auth command handlers, add operator attribution to the saga-transitions table, ship `MarkShipFailed` with saga compensation mirroring `MarkPickFailed`, add a tier-3 carrier-retry integration test exercising the Polly retry path through HTTP, and capture the Picker/Dispatcher MFA + first-login deferrals as production-hardening obligations in Auth AGENTS.md. Patch version bump `v0.16.1-sprint-12.5` matching the Sprint-X.5 cadence (2.5 / 4.5 / 7.5 / 8.5 / 10.5).

---

## Problem Frame

Sprint-12 shipped the Dispatcher role end-to-end and proved the 3-role hand-off workflow, but it left five concrete trade-offs on the table — captured in [`docs/phase-gates/2026-05-22-sprint-12-signoff.md`](../phase-gates/2026-05-22-sprint-12-signoff.md) and the CLAUDE.md "carried forward" list. Each gap has a visible cost on the existing system:

- The `auth_audit_log` table ships with a documented contract (15 EventType keys per `IAuthAuditLogRepository`) but no Application command handler currently calls `AppendAsync`. Every login, MFA, password-reset, and role-permissions change goes un-audited despite the storage layer being in place since Sprint-9.
- The `outbound_saga_transitions` table records every state change with `correlation_id` (Sprint-7), but there is no column capturing *which operator* triggered an operator-initiated transition. The 3-role hand-off proof (Sprint-12 U4) cannot reconstruct who confirmed each step from the audit trail.
- `MarkShipFailed` does not exist — the saga has a `PickFailed` compensation path (Sprint-3-redux Path B) but no analogous failure path at the `Packed` state. If a Dispatcher needs to abandon a ship attempt, the current options are leaving the order stuck in `Packed` or manually mutating the DB.
- The carrier-retry path (Polly v8 pipeline wrapping `MockShippingProvider`) has unit-test coverage (`MockShippingProviderTests`) but no end-to-end coverage exercising HTTP → controller → resilience pipeline → mock provider. Sprint-12 adversarial-F6 flagged this as a tier-3 gap.
- The Sprint-12 trade-off list named MFA enforcement for Picker/Dispatcher and force-change-on-first-login as "production-hardening" deferrals, but Auth AGENTS.md captures the MFA position only at deployment-guidance level and does not name force-change at all.

The CLAUDE.md trade-off line conflated two distinct audit workstreams ("`auth_audit_log` wiring on `ConfirmShipHandler`"), but source verification showed `auth_audit_log`'s schema is auth-event-only by design (all 15 keys are `auth.*`-prefixed). The two audit gaps need separate units.

## Requirements

**Auth audit log wiring**

- R1. Each of the 14 Auth Application command handlers must call `IAuthAuditLogRepository.AppendAsync` once per terminal outcome with the appropriate EventType key from the 15 documented in `IAuthAuditLogRepository` XML docs (login.success / login.failed / login.locked / refresh.success / refresh.reused / logout / password.changed / password.reset.requested / password.reset.completed / mfa.enrolled / mfa.used / mfa.disabled / mfa.reset_by_owner / account.unlocked_by_owner / role_permissions.changed).
- R2. Audit writes must be fire-and-forget — a write failure (Postgres unavailable, schema drift, etc.) logs the failure and does NOT propagate to the calling auth path's HTTP response.
- R3. The `metadataJson` field must capture event-type-relevant context (e.g., for `auth.refresh.reused`: the affected chain_id; for `auth.role_permissions.changed`: the diff of added/removed keys; for `auth.login.failed`: the reason code).
- R4. The Sprint-9 `auth_audit_log` table schema is unchanged for this unit — no migration ships with R1-R3.

**Outbound saga actor attribution**

- R5. The `outbound_saga_transitions` table must carry an `actor_user_id` (`Guid?`, nullable) column. Rows from operator-initiated endpoints (ConfirmPick / MarkPickFailed / ConfirmPack / ConfirmShip / MarkShipFailed) must populate it with the JWT subject of the calling user; rows from system-triggered transitions (StockReserved → AwaitingPick, StockReleased counter-drain → Cancelled, etc.) must leave it NULL.
- R6. The actor_user_id flows from the controller (via the existing JWT-aware request context) through the saga event payload to `SagaTransitionObserver.RecordTransitionAsync`. Sprint-7's existing observer wiring is the integration point.
- R7. An additive migration ships with the unit: `ALTER TABLE outbound_saga_transitions ADD COLUMN actor_user_id uuid NULL`. Historical rows backfill to NULL (no retroactive attribution needed for portfolio scope).

**`MarkShipFailed` feature**

- R8. A new endpoint `POST /api/v1/outbound/orders/{id}/mark-ship-failed` accepts a JSON body containing a non-empty `reason` string. The endpoint is gated by `[Authorize(Policy = PermissionKeys.OutboundOrdersShipConfirm)]` — the same policy that gates ConfirmShip. No new permission key is introduced; the Dispatcher + Owner baselines remain unchanged.
- R9. If `Order.Status != AwaitingShip`, the endpoint returns 422 with errorCode `order.invalid_state`. No saga event is published; no audit row is written. (Matches the ConfirmPick / MarkPickFailed precedent and Sprint-12 adversarial-F3 ordering invariant — the `[Authorize(Policy)]` filter still fires before the pre-state check.)
- R10. On success, the handler publishes a new `ShipFailed` saga event analogous to `PickFailed`. The `FulfillmentSaga` transitions `Packed → CompensatingReservation`, publishes one `ReleaseStockV1` envelope carrying the order's line SKUs, and waits for `StockReleased` arrivals to drain the counter. Terminal state is `Cancelled`.
- R11. The saga's `CompensatingReservation` IfElse `WhenEnter` activity must accept a third entry path (Path C — Packed + ShipFailed). Path C's counter-drain logic matches Path B (pick-failed): the `LinesAwaitingRelease` counter populates from the reserved-lines snapshot captured at `Reserved`, and the saga transitions to `Cancelled` once the counter reaches zero. Sprint-3-redux Path B logic is reused, not duplicated.
- R12. The endpoint is idempotent on the `Idempotency-Key` HTTP header (matches MarkPickFailed precedent and Sprint-11 KTD3 `createIdempotentMutation` pattern).

**Tier-3 carrier-retry E2E**

- R13. A new `[Fact(Skip = ...)]` integration test in `tests/ShopFlow.Outbound.IntegrationTests/Handoff/` exercises the carrier-retry path end-to-end: HandoffFixture configured with `MockShippingProvider.WithFlakeRate(0.5)` plus shortened min/max delays, ConfirmShip invoked through the HTTP client, assertions confirm the Polly v8 pipeline performed ≥1 retry, ≤4 total attempts, and ultimately returned a successful `ShippingLabel`. Skip-marked locally per Sprint-1+ posture; CI runs unskipped.
- R14. The test's total wall-time budget is under 5 seconds. Per-attempt delay must use the existing `MockShippingProvider` min/max-delay knobs configured at ≤50ms each — not real production 1-3s delays.

**Documentation deferrals**

- R15. Auth AGENTS.md gains an explicit subsection naming Picker/Dispatcher MFA enforcement and force-change-on-first-login as production-hardening obligations, with rationale referencing the Sprint-12 + Sprint-12.5 trade-off lists. Each item names what code change is required when implemented (so future-self does not need to re-discover scope).
- R16. Sign-off commit ships: `docs/phase-gates/2026-05-26-sprint-12.5-signoff.md`, CLAUDE.md current-stage paragraph update, CHANGELOG entry, and annotated git tag `v0.16.1-sprint-12.5`.

## Acceptance Examples

- AE1. **Covers R1, R2.** Given the `auth_audit_log` write fails (Postgres unavailable during the audit insert), when `LoginCommandHandler` completes a successful credential check, the 200 response is still returned with the access/refresh token pair; the audit failure is logged at Warning level and not surfaced to the client.
- AE2. **Covers R5, R6.** Given a `StockReservedV1` event arrives at the saga from the Inventory module, when the saga transitions `AwaitingReservation → Reserved`, the new row in `outbound_saga_transitions` has `actor_user_id IS NULL` (system-triggered transition).
- AE3. **Covers R5, R6.** Given a Dispatcher with user-id `D` calls `POST /api/v1/outbound/orders/{id}/confirm-ship`, when the saga transitions `Packed → Shipped`, the new row in `outbound_saga_transitions` has `actor_user_id = D`.
- AE4. **Covers R8, R9.** Given an order in state `Picked` and a Dispatcher JWT, when the Dispatcher calls `POST /mark-ship-failed` with reason "label rejected by carrier", the response is 422 with errorCode `order.invalid_state`; no saga event is published; no audit row is written; the order's status remains `Picked`.
- AE5. **Covers R10, R11.** Given an order in state `Packed` with three reserved line SKUs, when a Dispatcher calls `POST /mark-ship-failed`, the saga transitions `Packed → CompensatingReservation` and publishes one `ReleaseStockV1` envelope listing all three SKUs; after three `StockReleased` events arrive (one per line), the saga transitions `CompensatingReservation → Cancelled`; the order's terminal status is `Cancelled`.
- AE6. **Covers R13, R14.** Given `MockShippingProvider.WithFlakeRate(0.5)` with a deterministic seed producing failure on the first attempt and success on the second, when ConfirmShip is invoked through the HandoffFixture HTTP client, the resilience pipeline records exactly 1 retry and returns a successful `ShippingLabel`; the test completes in under 5 seconds wall-clock.
- AE7. **Covers R8.** Given a Picker JWT (Sprint-11 baseline, no `outbound.orders.ship-confirm` key), when the Picker calls `POST /mark-ship-failed`, the response is 403 with errorCode `auth.forbidden`; no saga event is published; no audit row is written. (Pins Sprint-12 adversarial-F3 ordering invariant for the new endpoint.)

## Key Decisions

- **Audit log split into two units.** Source verification revealed the CLAUDE.md trade-off line ("`auth_audit_log` wiring on `ConfirmShipHandler`") conflated two distinct tables. `auth_audit_log` is auth-event-only by design (15 keys all `auth.*`-prefixed); `outbound_saga_transitions` is the saga-state audit table. Wire each to the handlers that match its schema, do not cross modules.
- **MFA + force-change deferred to docs, not code.** Sprint-12.5 stays cleanup-shaped. Enforcement is real product behavior that affects every login and JWT-issued test — landing it alongside cleanup conflates two sprint shapes. Production-hardening sprint owns enforcement.
- **`MarkShipFailed` structurally mirrors `MarkPickFailed`.** Same idempotency pattern (Sprint-11 KTD3), same compensation shape (Sprint-3-redux Path B reused as Path C), same permission gate. Maximum reuse, minimum new surface area.
- **No new permission key for `MarkShipFailed`.** Reuses `outbound.orders.ship-confirm`. Dispatcher + Owner baselines unchanged; Sprint-12 KTD1 ADDITIVE-ONLY re-seed contract preserved.
- **Tier-3 E2E uses shortened mock delays.** `MockShippingProvider.WithFlakeRate(0.5)` plus min/max-delay knobs set to ≤50ms keeps total wall-time under 5 seconds. The retry path's correctness is independent of real production 1-3s carrier latency.
- **Patch version bump `v0.16.1-sprint-12.5`.** Matches Sprint-2.5 / 4.5 / 7.5 / 8.5 / 10.5 precedent — cleanup-shaped point releases get patch bumps. Sprint-9.5 / 11 / 12 used minor bumps for net-new role or feature surfaces; Sprint-12.5 has none.
- **Unit ordering: Auth audit wiring → Outbound actor column → MarkShipFailed.** The actor column must exist before `MarkShipFailed`'s saga publish writes a transition row, otherwise that row writes with NULL attribution and needs retrofit. Unit ordering is load-bearing.

- Assumes `MockShippingProvider.WithFlakeRate(flakeRate, minDelayMs, maxDelayMsExclusive)` test builder remains accessible to `HandoffFixture` after the Sprint-12 KTD5 factory-override pattern (no signature changes).

- Assumes the existing `SagaTransitionObserver.RecordTransitionAsync` signature can be extended to accept a nullable `Guid? actorUserId` without ripple through Sprint-7's 9 instrumented transition sites (one signature change, 9 call-site updates — additive, not breaking).
