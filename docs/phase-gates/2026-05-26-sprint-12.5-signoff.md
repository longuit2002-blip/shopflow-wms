# Sprint-12.5 Sign-off — Trade-off closures

Closes [Sprint-12.5 plan](../plans/2026-05-26-001-feat-sprint-12.5-trade-off-closures-plan.md) U0-U5. Ships as a ~1-week patch release on top of `v0.16.0-sprint-12`. Matches Sprint-X.5 cadence (2.5 / 4.5 / 7.5 / 8.5 / 10.5).

## Summary

Sprint-12.5 closes the five Sprint-12 trade-offs explicitly carried forward in the Sprint-12 sign-off "carried forward" list:

1. **Auth audit log wiring** — every Auth Application command handler that maps to one of the 15 documented EventType keys now writes to `auth_audit_log` via a shared `AuthAuditWriter` helper. Closes the Sprint-9 storage-but-unused gap.
2. **`outbound_saga_transitions.actor_user_id`** — operator JWT subject propagates from `IRequestContext.UserId` through saga event payloads into the new audit column. System-triggered transitions write NULL.
3. **`MarkShipFailed` + Path C compensation** — new `POST /api/v1/outbound/orders/{id}/mark-ship-failed` endpoint; saga gains `During(Packed, When(ShipFailed))` clause transitioning to CompensatingReservation. Path C reuses Sprint-3-redux Path B compensation primitives unchanged (no new IfElse branch, no new saga-state column).
4. **Tier-3 carrier-retry E2E** — Docker-backed Skip-marked integration test exercises the Polly v8 retry pipeline through HTTP using `MockShippingProvider` with an additive injectable `Func<double>` random source.
5. **MFA + first-login deferrals captured** — Auth AGENTS.md gains a `## Production-hardening obligations` section naming both deferrals with the code changes each requires when implemented.

## Key Technical Decisions (10)

Documented in U0 opening commit body and in the plan:

1. **KTD1** — Audit fire-and-forget at handler call site, NOT in repository. `AuthAuditWriter.TryAppendAsync` wraps try/catch + Warning log around the awaited call. Best-effort with exception suppression NOT latency-isolation.
2. **KTD2** — Audit-log scope is 12 handlers / 15 documented EventType keys, NOT all 16. BeginEnrollMfa / GenerateRecoveryCodes / CreateUser / UpdateUser have no documented key (Sprint-13+ catalog expansion).
3. **KTD3** — Actor propagation via saga event payload with explicit `Guid? ActorUserId = null` positional-default. Preserves backward-compat with existing test fixtures.
4. **KTD4** — `IRequestContext.UserId` is canonical JWT subject accessor on Outbound controller paths. Defensive fallback to `User.FindFirstValue(ClaimTypes.NameIdentifier)` only if null.
5. **KTD5** — Path C reuses Path B compensation primitives unchanged. Existing `WhenEnter(CompensatingReservation, IfElse(...))` handles Packed entry transparently — no third IfElse branch, no new saga-state column.
6. **KTD6** — `MarkShipFailed` idempotency = natural-409 pre-state check. Source verification confirmed `MarkPickFailedAsync` has no `Idempotency-Key` header processing; brainstorm's "header-keyed precedent" claim was factually wrong; plan corrects it.
7. **KTD7** — Tier-3 E2E determinism via injectable `Func<double>` random source on `MockShippingProvider`. `ConcurrentQueue<double>` required under Polly thread-pool retries.
8. **KTD8** — Patch version bump `v0.16.1-sprint-12.5` matching Sprint-2.5/4.5/7.5/8.5/10.5 precedent for cleanup-shaped point releases.
9. **KTD9** — `auth.login.failed` audit stores `submittedEmail` in `metadataJson` as deliberate forensic trade-off. HTTP response stays uniform per Sprint-9 R6; PDPA erasure bounded by per-tenant DROP DATABASE.
10. **KTD10** — `MarkShipFailedRequest.Reason` AND `MarkPickFailedRequest.Reason` BOTH carry 1000-character max-length. Closes inherited DoS / outbox-bloat vector.

## Deviations from plan

- **U1 `AuthAuditWriter` helper class**: plan said scatter try/catch + Warning log across each of the 12 handlers. Subagent implemented as `AuthAuditWriter.TryAppendAsync` shared helper + `AuthAuditEventTypes` constants. Reduces ~150 lines of duplicate boilerplate. Sprint-12.5 doc-review walkthrough framed this as improvement, not deviation requiring escalation.
- **U1 created 7 new handler test files** (Forgot, ResetPwdConfirm, VerifyEnrollMfa, VerifyMfa, DisableMfa, AdminMfaReset, AdminUnlockAccount). Plan said "extend existing"; no existing files for those 7 — fresh files were the necessary path.
- **U2+U3 shipped as single combined commit** `8babea0` rather than two commits. The two units touch the same files (FulfillmentSaga.cs + OrdersController.cs + saga event records); partial-file commit split would have been mechanical with no informational value. Plan's U2-then-U3 ordering is a brainstorm-to-plan handoff distinction, not an execution-time requirement.
- **U2+U3 implemented inline in main worktree** rather than the originally-dispatched parallel subagent. The U2+U3 worktree subagent's sandbox was created with a stale Sprint-5 baseline (`06febb2`) and could not safely operate cross-worktree from there. Reset + re-dispatch wasn't worth the time; inline execution in the main worktree completed in similar wall-time.
- **U4 deterministic seed polarity correction**: plan brief stated retry-success sequence `[0.9, 0.1]`. `MockShippingProvider.cs:107` flake check is `_randomSource() < _flakeRate` — LOW value flakes, HIGH succeeds. Subagent inverted to `[0.1, 0.9]` for retry-success and `[0.1, 0.1, 0.1, 0.1]` for retry-exhaust. Comments and docstrings reflect the actual polarity.
- **`--no-verify` used on commits**: `.husky/_/husky.sh` is absent on this dev machine (documented in CLAUDE.md as known state since Phase-0-redux). CI's `csharpier --check` runs full validation. Sprint-12 + earlier commits used the same posture.
- **CHANGELOG entry placement**: appended after Sprint-12 entry maintaining the canon-supersession history shape. Sprint-12.5 is NOT a canon supersession (no ADR change) but it is a tagged release worth tracking.
