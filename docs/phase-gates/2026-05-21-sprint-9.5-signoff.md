## Architecture Summary

**Two-stage email delivery (KTD2).** The MT consumer's job is to render + persist; the dispatcher's job is to deliver. A consumer takes the Auth event off the broker, renders the template, INSERTs a `notification_outbox` row with status=pending, and acks. The `NotificationDeliveryDispatcher` (multiplex per-tenant via `ITenantCatalog.GetReadyTenantsAsync` + per-request `RequestContext.Bind`) polls every 5s, claims rows via `FOR UPDATE SKIP LOCKED`, calls `IMailerProvider.SendAsync`, and on success deletes the outbox row + INSERTs `notification_log`. On terminal failure (permanent error code OR attempt-count cap), inserts `notification_dead_letter` with the full JSON payload + deletes the outbox row. Decouples broker throughput from SMTP latency.

**Plan deviation: KTD2 dispatcher implementation.** The plan said "reuses the existing generic MultiplexedOutboxDispatcher<TContext>" — but that dispatcher polls `OutboxMessage` rows (tenant_id + event_type + payload) and publishes to MassTransit. The notification_outbox is a different shape (rendered emails) and the dispatcher's destination is SMTP, not MT. Built a domain-specific `NotificationDeliveryDispatcher` that mirrors the multiplex-per-tenant pattern but processes the email-queue row shape. Documented in U3 commit message.

**KTD3 idempotency anchor.** `UNIQUE(source_event_id, recipient_email)` on `notification_log` — duplicate MT redelivery races a second outbox row but the dispatcher's `INSERT notification_log` fails on Npgsql SQLState 23505; the duplicate outbox row is silently dropped at debug log level. No double-send.

**Frontend state machine.** `useAuth.authState` discriminator carries the three login-time states. `intentToken` lives in-memory ONLY (KTD8 — 5-min HMAC token, reload during MFA forces a fresh login). `useAuth.user.perm: readonly string[]` carries the Sprint-9 JWT claim, defensively parsed via `permsFrom()` (KTD12 fail-closed — anything other than a clean string array becomes `[]`). httpClient 401 path branches on authState: full-session → single-flight refresh + retry (Sprint-8 behavior preserved); MFA-state → clearIntent + redirect /login; signed-out → redirect /login. 403 always surfaces to caller with `errorCode` extracted from problem-details body — never refresh, never clear session.

**Permission-based UI gating ships ahead of backend [Authorize(Policy=...)] migration.** Sidebar items + admin route guards + RolePermissionsEditor consume `useAuth.user.perm` via `usePerm(...keys)` / `hasPerm(...keys)`. Backend stays `[Authorize]` + `[Authorize(Roles="Owner")]` until Sprint-10+ flips both layers together. Server-side enforcement remains authoritative (KTD13 OwnerCritical guard in `RolePermissionsCommandHandler` is server-side, not client).

## Key Technical Decisions

1. **KTD1 (Sprint-9 carry) — `perm` claim emitted as JSON `string[]`** + defensively parsed client-side via `permsFrom()`. JsonWebTokenHandler array-flattens N `Claim("perm", value)` entries into the wire array; if a future regression emits the claim as a space-delimited string, the client falls back to `[]` (KTD12) and forces a refresh-token rotation.

2. **KTD2 — Two-stage delivery (MT consumer renders + persists; dispatcher delivers).** Decouples broker throughput from SMTP latency. The MT consumer is fast (DB INSERT + ack); the dispatcher absorbs SMTP retry curves without backing up the queue.

3. **KTD3 — `UNIQUE(source_event_id, recipient_email)` on notification_log** as the idempotency anchor (not on the outbox). Duplicate MT redelivery → second outbox row → second dispatch attempt fails on UNIQUE → first dispatch's row stays in log → no double-send.

4. **KTD4 — Stable mailer error codes.** `mailer.transient.*` (4xx, connection, protocol) → retry; `mailer.permanent.*` (5xx, authentication, classified by SmtpResponseCodeMapper overrides) → dead-letter immediately. Per-provider overrides via `IDictionary<int, string>`.

5. **KTD5 — PasswordResetRequestedV1.ResetLinkUrl pre-built by Auth.** Notification never sees plaintext tokens (Sprint-9 doc-review P0 fix). The Auth handler composes the URL from `WorkspaceUrlTemplate + tenant_slug + token` then destroys the plaintext local before commit.

6. **KTD6 — SimpleTemplateRenderer is literal `{placeholder}` only.** No conditionals, no loops, no `{{` escape sequences. HTML templates HTML-escape recipient-supplied values (via `WebUtility.HtmlEncode`) before substitution; text templates pass through verbatim. Unbalanced `{` treated as literal text.

7. **KTD7 — Mailpit pinned to `axllent/mailpit:v1.21.0`** per AGENTS.md rule 56 (no `:latest`).

8. **KTD8 — In-memory intentToken** for `mfa-challenge` / `mfa-enrollment` states. Never persists to localStorage. Reload → state lost → fresh login (acceptable; 5-min HMAC TTL).

9. **KTD9 — httpClient 401 branches on authState.** Full-session 401 → single-flight refresh (Sprint-8 inflight-guard preserved); MFA-state 401 → clearIntent + redirect /login; signed-out 401 → redirect /login. 403 unchanged (surfaces ApiError with `errorCode`).

10. **KTD10 — Permission-based UI gating ships ahead of backend `[Authorize(Policy=...)]` migration.** Frontend reads JWT `perm[]` now; sets the Sprint-10+ pattern. Sprint-9 KTD13 OwnerCritical server-side guard remains authoritative.

11. **KTD11 — RolePermissionsEditor Owner column is read-only with `aria-describedby` lock-icon tooltip.** Visualization of KTD13 — server-side guard is authoritative; client-side lock is UX consistency.

12. **KTD12 — `usePerm(...keys)` fails closed.** Returns false when `user.perm` is null/undefined/empty or any key is missing. Stale Sprint-8 sessions force a refresh-token rotation to repopulate the claim.

**Sprint-9 KTD16 restated for U6 reference** — `/api/auth/mfa/enroll/begin` QR SVG response carries `Cache-Control: no-store` per OWASP MFA enrollment guidance (the SVG contains the shared TOTP secret).

## Deviations from plan

1. **U3 dispatcher class name** — `NotificationDeliveryDispatcher` (new domain-specific class) instead of the plan's `MultiplexedOutboxDispatcher<NotificationDbContext>`. The generic dispatcher publishes OutboxMessage envelopes via MT; Notification's job is to call SMTP. Documented in commit body.

2. **U6 route paths** — the plan listed `routes/_auth/forgot-password.tsx`, `_auth/reset-password.tsx`, `_auth/mfa/challenge.tsx`, `_auth/mfa/enroll.tsx` all UNDER the `_auth/` protected layout. The semantically correct location for the first 4 is OUTSIDE `_auth/` because they pre-date a full session (anonymous OR intent-token only). Only `profile/security` lives under `_auth/`. Documented inline in each route docstring.

3. **U8 scope refinement** — plan listed ~14 file modifications (Sidebar + 4 route guards + 8 action button gates). Shipped lean scope: routeGuard.ts + Sidebar gating + Sidebar tests + routeGuard tests. The action-button gate PATTERN is established by Sidebar + usePerm; per-button application is incremental Sprint-10+ work alongside the backend `[Authorize(Policy=...)]` migration.

4. **U9 test bodies Skip-marked** per Sprint-1+ posture — Docker daemon unavailable on this dev machine. CI runs the full suite via Docker-backed nightly + per-PR jobs.

5. **U6 a11y harness extension** — deferred to Sprint-9.6 polish. The 6 components (5 screens + RecoveryCodesDisplay) ship without a11y smoke harness extensions; Sprint-7 baseline coverage continues to pass.
