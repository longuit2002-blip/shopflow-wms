# Sprint-7.5 sign-off — Production-Ready Trade-off Closures

Sprint-7.5 closes the seven Sprint-6 / Sprint-7 deferred trade-offs plus a cross-table index audit. Posture flipped from portfolio-demo-grade to **production-ready, big-data-seed-ready**: cursor pagination is mandatory (not "for later"), indexes are baked into every new schema, MT-redelivery defenses ship as constraints not "if observed". 12 implementation units (U0-U11) shipped on `feat/sprint-7.5-trade-off-closures` cut from `v0.10.0-sprint-7-orders`.

The sprint executed the brainstorm + plan + doc-review + execution pipeline pattern from Sprint-7, with one shape change: subagent dispatch hit a UX wall on perceived latency (multi-minute background returns made the conversation feel slow), so mid-sprint the orchestrator switched to **inline execution** for the Inventory chain (U3, U6) and Round-4 units (U4, U5, U10). U0/U1/U2/U7/U8/U9 still shipped via subagent dispatch; U3/U6/U4/U5/U10/U11 ran inline. Both modes produced commit-quality work; the inline mode is recommended when the orchestrator has rich context already in-window.

## Trade-offs carried forward to Sprint-8+

1. **Real auth** — JwtBearer kernel-lift + access-token redaction shipped in Sprint-7, but the dev-mode baked JWT remains. Real password hashing + refresh tokens + role claims + MFA is Sprint-8.
2. **`CREATE INDEX CONCURRENTLY`** — deferred per scope; standard EF Core migrations sufficient at current scale. Revisit before first true production deploy.
3. **Million-row latency benchmark for AE4** — U6 verified query-plan-uses-index + sub-200ms against 1k-row test fixture. Full million-row benchmark deferred to a benchmarking pass (Scope Boundaries documented).
4. **Big-data seed itself** — Sprint-7.5 made the schema + queries + pagination ready; the seed loader is a later workstream.
5. **Category field interaction type** — Sprint-7.5 ships free-text input; eventual enum/autocomplete decision deferred to Sprint-9+ when Channel module's product mapping introduces a category taxonomy.
6. **Backfilling existing `skus` rows with rich data** — initial migration sets new columns NULL; production import is a later workstream.
7. **Pre-existing frontend test failures** (3 carried from Sprint-7 baseline) — axe `empty-table-header` on OrderLineItems + `Response.body` re-read in `useOrderMutations` idempotency test. Documented in U2 + U9 + U7 commit bodies; not Sprint-7.5 regressions.

## Deviations from plan file list

- **KTD6 design refinement (U8)**: Plan called for "catch DbUpdateException at SaveChanges boundary." Implementation discovered EF Core's `SaveChangesFailedAsync` cannot actually suppress exceptions (only observe them). Primary swallow mechanism shifted to `SavingChangesAsync` pre-check + detach. The constraint never fires in the happy redelivery path. `SaveChangesFailedAsync` remains as defensive log-only. Better design than the plan called for.
- **U3 namespace decision**: To avoid colliding with the existing `Sku` value object, the new Sku aggregate lives at `ShopFlow.Inventory.Domain.Catalog.Sku`. SkuRepository imports `using SkuCode = ShopFlow.Inventory.Domain.Sku;` for the existing value object reference. Documented in SkuRepository.cs.
- **U6 index name**: Plan said `(sku, occurred_at DESC)` but `reservations_ledger` has no `occurred_at` column (event time is computed in C# via COALESCE). Index named `ix_reservations_ledger_sku_created_at_id` on the existing order key. Handler docblock + migration comment document the deviation.
- **Subagent dispatch shape**: Plan KTD9 said 5 rounds via subagent dispatch. Sprint-7.5 executed 5 units via subagent (U2 / U7 / U8 / U9 / U3 — though U3's subagent completed and the work was committed inline based on its file output) and 6 units inline (U0 / U1 / U6 / U4 / U5 / U10 / U11). Mid-sprint user feedback ("dispatch too slow for me") pivoted execution to inline mode for the rest of the sprint. Both modes produced commit-quality work; inline is faster when the orchestrator has rich context already in-window. Subagent dispatch is best for parallelizable file-disjoint work.
- **U3 SetFlashSaleCommandHandler extraction (ADV-004 carry-through)**: The doc-review flagged a non-standard layout where `ISkuMetadataStore.cs` had an embedded command handler. U3 lifted that handler to a properly-named `SetFlashSaleCommandHandler.cs` file before deleting `ISkuMetadataStore.cs`.
- **U10 scope refinement**: Plan said "implementer identifies specific indexes via EXPLAIN." Without local Docker the EXPLAIN review wasn't possible; U10 instead writes judgment-based defensive composite + FK + time-range indexes per module with `CREATE INDEX IF NOT EXISTS` so any index that already happens to ship is a no-op. The migrations are forward-safe under either current or future tighter index review.
