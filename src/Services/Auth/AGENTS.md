# Auth module — agent invariants

Sprint-8 + Sprint-9 ship the real auth surface. Plaintext credentials cross the `IPasswordHasher` boundary only; rest of the system handles PHC strings, opaque refresh tokens, and AES-GCM-encrypted TOTP blobs. Sprint-10 lifts the gating mechanism on `AuthAdminController` from class-level `[Authorize(Roles="Owner")]` to per-action `[Authorize(Policy = PermissionKeys.X)]`.

## Hard rules

- **Sprint-10 gating shape**: `AuthAdminController`'s 9 actions carry per-action `[Authorize(Policy = PermissionKeys.X)]` referencing the 9 keys in `PermissionKeys.OwnerCritical`. Class-level `[Authorize(Roles="Owner")]` is removed. Safety nets that prevent Owner lockout: `RolePermissionsSeed` (Sprint-9 U12) bootstraps Owner with all 24 keys at every tenant provision; KTD13 `OwnerCritical` guard in `RolePermissionsCommandHandler` rejects any edit that would shed an admin key from Owner; Sprint-10 U4 `AuthAdminAuthorizePolicyCoverageTests` dual-pins the AuthAdmin policy set against `PermissionKeys.OwnerCritical`. `AuthController` self-service endpoints (logout / me-password / mfa-enroll-begin / mfa-disable / mfa-recovery-codes) keep bare `[Authorize]` — no perm key for self-service over the authenticated user, by design.
- **Sprint-10.5 runtime enforcement + hub policy**: 33 Docker-backed 403 wire-shape tests at `tests/ShopFlow.<Module>.IntegrationTests/Authorization/<Module>403Tests.cs` + 1 cross-tenant boundary test pin every Sprint-10 action's enforcement behavior at runtime; shared `NarrowedJwtBuilder` issues JWTs with caller-supplied `perm[]`. `TenantHub` carries `[Authorize(Policy = PermissionKeys.HubConnect)]` (Sprint-10.5 U3); the bare `[Authorize]` is dropped. `tests/ShopFlow.SharedKernel.IntegrationTests/Authorization/AdminTsCatalogContractTests` pins frontend `web/src/api/admin.ts` ↔ backend `PermissionKeys.All` set equality at test time (filesystem-only, no Docker) — drift in either direction fails CI. `tests/ShopFlow.SharedKernel.UnitTests/Authorization/PolicyRejectionPathTests` (adv-3) exercises `IAuthorizationService.AuthorizeAsync` rejection on a deficient principal locally, bisecting framework / JWT / policy regressions ahead of the Docker suite.
- **Sprint-10.5 SEC-001 carry**: legacy tenants brought up via raw `shopflow-migrate apply` lack `role_permissions` rows; `RolePermissionsSeed` only runs on `provision` or explicit `seed-owner`. Pre-Sprint-9 tenants MUST be reseeded via `shopflow-migrate seed-owner --tenant=<slug>` before deploying Sprint-10.5 or their Owner cannot connect to `TenantHub` (hub.connect missing from the JWT).
- **Sprint-11 Picker baseline**: `RolePermissionsSeed` pre-seeds Picker with 4 keys at every tenant `provision` / `seed-owner` run: `outbound.orders.read` + `outbound.orders.pick-confirm` + `inventory.read` + `hub.connect`. **ADDITIVE-ONLY contract (KTD1)**: re-running provisioning preserves Owner-added keys via `ON CONFLICT (role, permission_key) DO NOTHING`, but Owner *deletions* from the baseline REVERT on the next provision run. Picker users are provisioned via the canonical `/admin/users` flow (Sprint-9 U7); Picker MFA is not enforced at Sprint-11 (Sprint-12+ hardening decision); force-change-on-first-login is not enforced (future production hardening).
- **Sprint-12 Dispatcher baseline**: `RolePermissionsSeed` pre-seeds Dispatcher with 3 keys: `outbound.orders.read` + `outbound.orders.ship-confirm` + `hub.connect`. Same KTD1 ADDITIVE-ONLY re-seed contract as Picker (Owner additions preserved; Owner deletions revert). **Dispatcher MFA recommended for production despite engine default**: `outbound.orders.ship-confirm` triggers real carrier-API label creation with cost implications — categorically different from Picker's internal saga transition. Operators SHOULD set `users.mfa_required = true` on Dispatcher accounts via the Owner admin surface until non-Owner MFA defaults are hardened. Documented as deployment-time guidance, not enforced by the engine. At Sprint-12 the hand-off chain was Picker → Owner → Dispatcher (Pack stayed Owner-only).
- **Sprint-13 Packer baseline**: `RolePermissionsSeed` pre-seeds Packer with 3 keys: `outbound.orders.read` + `outbound.orders.pack-confirm` + `hub.connect` (Dispatcher-shape, no `inventory.read` — items are pulled by pack time). Same KTD1 ADDITIVE-ONLY re-seed contract. Pack-confirm moves OFF Owner-only; the hand-off chain is now **Picker → Packer → Dispatcher** on one saga (Owner retains pack-confirm via ADDITIVE-ONLY but is no longer required for the happy path). `UserRole.Packer` is the 4th enum value (index 3); migration `20260527000001_AddPackerRole` widens BOTH `chk_users_role` AND `chk_role_permissions_role` to include `'Packer'`. **Operator deployment requirement (ADV-002/ADV-008)**: deploying Sprint-13 against an EXISTING tenant requires re-running `shopflow-migrate provision --tenant=<slug>` (or `seed-owner`) AFTER the migration applies — the migration widens the CHECK constraint but inserts no rows, so a Packer user created before the re-seed would have an empty `perm[]` and get 403 everywhere. New-tenant provisioning is unaffected (it runs the seed inline). `mark-pack-failed` reuses the `outbound.orders.pack-confirm` policy (no 25th key); Packer MFA carries the same deployment guidance as Dispatcher.
- **R6 enumeration discipline**: every credential failure leg collapses to `auth.invalid_credentials` + 401. No leg leaks "missing user" vs "wrong password" vs "locked" vs "tenant unknown" — see `LoginCommandHandler` + `ResolveTenantAsync` in `AuthController` for the canonical shape.
- **KTD5 single-source config**: `Auth:DevSecret` + `Auth:Issuer` + `Auth:Audience` are read by JwtTokenIssuer, the kernel JwtBearer validator, AND the HMAC MFA challenge codec. Bump one and you bump all three.
- **KTD1 perm claim shape**: `perm` is a JSON string array (one `Claim("perm", value)` per key). The U7 policy registration uses `RequireClaim("perm", <key>)` which matches element-by-element. Do NOT space-delimit.
- **KTD2 chain-only revoke**: post-grace refresh-token reuse detection calls `IRefreshTokenStore.RevokeChainAsync(chain_id)`, NOT `RevokeAllForUserAsync`. Other devices on independent chains keep working.
- **KTD3 tombstone TTL 7d**: grace check is code-level `now - RotatedAt < RotationGraceWindowSeconds`, NOT Redis TTL expiry. Tombstone payload carries `chain_id` + `rotated_at`.
- **KTD7 ForwardedHeaders gate**: non-Development boot throws when `Auth:ForwardedHeaders:KnownProxies` and `:KnownNetworks` are both empty. Forge-resistant.
- **KTD8 KEK rotation**: TOTP secret blobs carry `totp_key_id`. Cipher reads `Current` then falls back to `Previous`. Per-row AAD = `tenant_id || user_id`.
- **KTD9 Argon2 dual-profile**: passwords use OWASP 2026 (m=64 MiB / t=4 / p=4); recovery codes use the lighter profile (m=8 MiB / t=2 / p=1). PHC string parameter-embedding lets Verify stay profile-blind.
- **KTD10 enrollment Redis 10-min TTL**: in-flight TOTP secrets live in Redis only. Never in JWT, never in process memory (modular monolith multi-instance under Aspire).
- **KTD13 OwnerCritical guard**: `RolePermissionsCommandHandler` rejects any edit that would leave Owner missing any `PermissionKeys.OwnerCritical` key. Server-side enforced.
- **KTD14 forgot-password constant-time**: unknown email + cooldown active both run a dummy Argon2 verify against `AuthPasswordResetOptions.SyntheticHash` to keep wall-time uniform.
- **KTD16 QR `Cache-Control: no-store`**: the otpauth SVG contains the shared TOTP secret. Any cache layer that persists it = secret leak.
- **R17 Owner-MFA invariant**: `AdminMfaResetCommand` rejects targeting an Owner with `MfaRequired=true` (`auth.mfa_required_invariant_owner`).
- **Sprint-12.5 audit-log wiring**: every Auth Application command handler that maps to one of the 15 documented `EventType` keys (12 handlers covering Login×3 / Refresh×2 / Logout / ChangePassword / ForgotPassword / ResetPasswordConfirm / VerifyEnrollMfa / VerifyMfa / DisableMfa / AdminMfaReset / AdminUnlockAccount / RolePermissions) writes to `auth_audit_log` via the shared `AuthAuditWriter.TryAppendAsync` helper at every terminal emit. **Best-effort with exception suppression, NOT latency-isolation** (KTD1): the helper wraps `AppendAsync` in try/catch + Warning log, but still awaits — under Postgres load the auth response inherits audit-write p99. True background-channel dispatch defers to Sprint-13+. **`auth.login.failed` stores `submittedEmail` in `metadataJson`** (KTD9) as a deliberate forensic trade-off for credential-stuffing analysis — HTTP response stays uniform per R6, PDPA erasure bounded by per-tenant DROP DATABASE. **`auth.login.locked` fires once at the lockout boundary attempt**, matching `AccountLockedV1` semantics. Source IP correctness depends on Sprint-9 KTD7's `ForwardedHeaders` middleware being wired with non-empty `KnownProxies` — see [`docs/solutions/2026-05-26-fire-and-forget-audit-write-pattern.md`](../../../docs/solutions/2026-05-26-fire-and-forget-audit-write-pattern.md). 4 of the 16 distinct command handlers (BeginEnrollMfa / GenerateRecoveryCodes / CreateUser / UpdateUser) have no documented EventType key and are intentionally NOT audited at Sprint-12.5 — Sprint-13+ catalog expansion (KTD2).
- **ADR-0003**: per-tenant DB hard isolation. No `tenant_id` column on any Auth table. Tenant context flows through `IRequestContext` + the per-request `AuthDbContext` binding.

## Production-hardening obligations

Sprint-12.5 documents two production-hardening obligations that ship as deferrals (decisions resolved at brainstorm time; enforcement deferred to a future sprint where the JWT-test-infrastructure churn lands together). Sprint-13 adds the Packer role under the same posture + one new deferral:

- **Picker / Dispatcher / Packer MFA enforcement**: at Sprint-13 only Owner is created with `MfaRequired=true` (`User.Create` checks role). Picker + Dispatcher + Packer can opt-in via `/profile/security` but the engine doesn't force it. Production deployments SHOULD set `users.mfa_required = true` for Dispatcher AND Packer accounts via the Owner admin surface (both trigger cost-bearing or commit-bearing transitions — Dispatcher's `outbound.orders.ship-confirm` does carrier-API label creation; Packer's `outbound.orders.pack-confirm` commits the order toward shipment). Code change when enforced: `User.Create` flips the default to `MfaRequired=role != UserRole.Owner` (or removed entirely if all roles default to true) + every test harness that issues non-Owner JWTs must pre-enroll MFA (`NarrowedJwtBuilder` extension) + a migration may need to flip historical rows.
- **`auth_audit_log` write-path on Outbound saga handlers (Sprint-13 carry)**: the Sprint-13 `MarkPackFailedHandler` (and the existing ConfirmPick/Pack/Ship + MarkPick/ShipFailed paths) do NOT write `auth_audit_log` rows. Actor visibility relies on the `actor_user_id` column on `outbound_saga_transitions` (Sprint-12.5 U2/U3). An Owner-granted-pack-confirm-on-Picker (adversarial-F8 / KTD1) is therefore invisible in `auth_audit_log` until the Outbound saga handlers are wired. Also unaddressed at Sprint-13 (SEC-004): a controller-driven `mark-*-failed` action with a NULL `IRequestContext.UserId` records a NULL-actor transition rather than rejecting with 401 — applying a NULL-actor guard is a cross-cutting change across all three mark-*-failed endpoints (kept consistent at Sprint-13, hardened together later).
- **Force-change-on-first-login**: not enforced at Sprint-12.5. `OwnerSeed`'s temp-password stdout echo (Sprint-8 U10) is the operator's current obligation to communicate + change at first login. Code change when enforced: new `users.must_change_password` column (default `true` on `CreateUserCommand` + `ResetPasswordConfirmCommand` + `OwnerSeed` apply paths), login flow returns an intent token like the MFA-challenge state with `must_change_password = true`, frontend redirects to `/me/password` before issuing a full-session JWT, `/me/password` clears the flag on completion.
